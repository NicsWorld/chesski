## 2024-11-20 - [chess.js game.board() Performance]
**Learning:** Calling `game.board()` in `chess.js` is computationally expensive because it dynamically generates a 2D array representation of the board state.
**Action:** Replace `game.board()` with iteration over the `SQUARES` constant and use `game.get(square)` to lookup pieces efficiently, especially in tight loops like rendering `ChessBoard`, rendering `CapturedPieces`, or parsing board state in `Tutorial`.
## 2024-05-19 - Avoid Re-rendering the Entire Chessboard on Drag
**Learning:** In a React chess game, when dragging a piece to see valid moves, the validMoves state updates in the parent ChessBoard. If squares/pieces are mapped directly inside the render loop, this state change forces all 64 squares and 32 pieces to re-render, even though only a few squares are highlighted.
**Action:** Extract the square/piece combination into a separate BoardCell component wrapped in React.memo(). By providing a custom equality function that checks prev.piece === next.piece and prev.highlight === next.highlight, we can ensure that ONLY the highlighted squares re-render when dragging starts, cutting component re-renders from ~96 down to exactly the number of valid moves (e.g. 2).
## 2024-05-19 - Use Primitive Props for Chess.js Pieces in React.memo
**Learning:** `chess.js`'s `game.get(square)` method returns a newly instantiated object on every single call (e.g., `{ type: 'p', color: 'w' }`). Because of this, using the piece object directly as a prop in a `React.memo` component (like a `BoardCell`) defeats the memoization, as `prev.piece === next.piece` always evaluates to false for occupied squares, causing them to re-render constantly. Additionally, using custom equality functions that ignore callback props on empty squares introduces dangerous stale closure bugs.
**Action:** Instead of passing the piece object to `React.memo` components, destructure the piece and pass its primitive properties (`pieceType={piece?.type}` and `pieceColor={piece?.color}`). The standard `React.memo` shallow comparison works perfectly with primitives, successfully eliminating re-renders without needing custom, error-prone equality functions.
